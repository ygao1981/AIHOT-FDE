# FDE 研究台：从资料到选题的个人工作流

FDE 研究台用于积累企业 AI 落地经验，再把经验整理成自己的项目判断与技术文章。最小工作流是：**收录原文 → 选择分析 → 核对证据 → 记录笔记 → 形成选题 → 导出写作**。

先用少量资料试一轮，确认研究结果符合你的判断标准，再扩大收集范围。模型分析是阅读辅助，原文与个人判断始终分开保存。

## 1. 进入工作区

打开部署后的研究台地址，输入部署时设置的**访问口令**。这不是模型服务的 API Key，不要在登录框填写模型密钥。

登录成功后，研究台通过服务器签发的会话 Cookie 维持访问。访问口令不会保存在浏览器的本地存储中。使用完毕可点击右上角“退出”。

工作区分为三个页面：

| 页面 | 用途 |
| --- | --- |
| 研究库 | 查找资料、阅读研究结果、保存个人笔记、推进选题与导出 |
| 信源 | 检查固定来源，选择哪些来源参与自动收集 |
| 用量 | 查看分析次数、已记录的 token、费用估算与运行状态 |

## 2. 收集值得研究的原始资料

### 先收少量、高相关性的材料

优先收集能回答下列问题的案例、教程或复盘：

- 客户或业务团队原先遇到了什么问题？
- 实施团队如何处理数据、系统集成、权限、评测和人员协作？
- 项目到了方案、演示、试点还是生产使用阶段？
- 效果怎么测量？有没有成本、限制和失败经验？
- 哪些做法能迁移到制造、物流、售后、知识库等自己的实际场景？

资料没有出现 “FDE” 一词，也可能值得收录。仅有招聘、融资、产品宣传或通用模型发布的信息，通常不能回答这些问题。

### 手动导入

点击“导入资料”，填写原文链接。标题和正文可以选填。网页无法完整读取时，粘贴有权使用的正文，并保留关键数据、适用条件与作者原话。

正文不足的资料会显示“待补正文”。打开该资料，点击“补充正文”，使用同一原文链接提交正文。更新正文后，旧分析需要按新内容重新判断，不应把旧结论继续当成新正文的结论。

不要粘贴访问口令、API Key、未经授权的客户资料或与研究无关的敏感内容。研究台保存来源链接，但不代替原文的使用授权。

### 固定信源

在“信源”页面查看来源说明，按研究方向启用或停用自动检查。停用来源不会删除已经收录的资料。

标记为“人工阅读”的来源提供直接阅读入口，不参与自动采集。可在读到具体文章后，把文章链接和正文手动导入。

“检查信源更新”会安排收集任务。采集关闭时，按钮不可用，仍可手动导入。**自动分析关闭时，检查来源不会因此调用分析模型。** 如果启用了自动分析，通过相关性检查的新资料可能继续进入分析队列。

原文未披露日期时，页面显示“原文未注明日期”。只有日期的数据按日期展示，不补造时分。语言只说明文章语言，不用于推断案例所在国家或地区。

## 3. 先选文章，再使用模型分析

建议首次选择约 5 篇资料，覆盖案例、实施教程和项目复盘，再逐篇点击“加入分析队列”。

这一步只安排异步任务。任务何时开始，还取决于分析是否启用、当前队列、暂停状态和用量上限。页面会自动刷新等待中的结果。需要时也可手动点击“刷新”。

| 分析进度 | 含义与处理方式 |
| --- | --- |
| 待分析 | 资料已保存，尚未安排模型处理 |
| 待补正文 | 可用正文不足；先补充正文 |
| 排队中 | 已安排任务，等待处理条件满足 |
| 分析中 | 已开始处理，等待结果 |
| 已分析 | 已有结构化研究结果，可开始核对 |
| 已跳过 | 资料未通过本地相关性规则，未调用模型，也不安排分析；仍可阅读、保存笔记或补充相关正文 |
| 分析未完成 | 结果未完成或不明确；先核对账号和用量，再决定是否重试 |

手动导入的资料也要通过本地相关性检查。被规则过滤后，不能直接安排模型分析；可以继续阅读、保存笔记，或补充与 AI 落地有关的原文后重新判断。本地过滤本身不会增加模型尝试次数，也不会因此暂停分析队列。

相同资料和分析设置会优先复用已有结果。点击“重新分析”或“确认后重试”前，界面会要求明确确认，因为新请求可能再次消耗额度。失败、中断、超时不等于没有消耗，系统不会以此推断费用为零。

## 4. 用原文核对研究结果

打开“查看研究”，先看**业务问题、实施方案、成效与结果**，再看可借鉴经验、适用条件、原文证据和阶段判断依据。

核对时至少检查四件事：

1. **阶段是否准确。** 计划、演示和试点都不能写成已经生产上线。“生产就绪”也不等于已有生产使用。
2. **效果是否有条件。** 成本下降、效率提升、准确率等数字，需要核对测量方法、对照基线、时间范围和适用场景。原文没有给出的效果，保留“原文未披露”。
3. **证据来自谁。** 厂商或实施方的自述，不等于客户独立确认，也不等于第三方复核。原文引文能支持某个表述，并不能自动证明所有推广结论。
4. **信息是否完整。** 正文提取可能不完整，分析也可能仅覆盖已提供的部分。打开“阅读原文”检查上下文、图表与附录。

“原文证据”中的引用来自收录正文；其下方的“分析对应要点”是对引用的解释。你仍需判断这种解释有没有超出原文含义。

“选题建议”单独展示。这些建议属于待写的编辑方向，不能当作已经发生的事实直接转述。

## 5. 保存自己的判断，推进选题

在“个人笔记”中记录你的判断，然后点击“保存笔记”。笔记支持最多 10000 个字符。

可以使用以下简短结构：

```text
我准备解决的问题：

原文中可以引用的事实与出处：

值得借鉴的实施方法：

放到自己的业务中，需要满足的前提：

还需核实的问题：

我的选题与写作角度：
```

关闭资料详情前，页面会提示未保存的修改。草稿只能暂留在当前页面，不能替代“保存笔记”。刷新、关闭页面或退出登录，都可能丢失未保存的草稿。

选题进度和分析进度彼此独立：

| 选题进度 | 建议用法 |
| --- | --- |
| 待整理 | 刚收录，尚未决定用途 |
| 已选题 | 已确认值得继续研究或写作 |
| 写作中 | 已开始搭建提纲、核对材料或写稿 |
| 已发布 | 自己已完成外部发布后，回来记录进度 |
| 已归档 | 暂不继续推进，但保留资料和笔记 |

“已发布”仅是个人进度标记。研究台不会把文章发布到公众号、网站或其他平台。

## 6. 导出后开展写作

资料详情中的“导出 Markdown”用于导出当前资料。研究库的“导出研究资料”用于导出可供研究使用的分析资料集合；没有分析结果或已归档的资料不计入这个集合。

导出文件保留原文入口、研究内容及个人笔记，便于继续整理提纲和写作。导出本身不会把文件自动发送到外部平台。

写作时保留事实来源，明确区分作者陈述、你核实过的事实和自己的判断。涉及客户效果时，优先写清业务背景、实施条件与验证方法，避免只保留一个漂亮的效果数字。

## 7. 看懂用量，控制处理节奏

“用量”页面分别展示滚动 24 小时分析尝试、本月已记录 token 和费用信息。本月统计按服务端 UTC 月份计算。

- **API 模式：** 根据部署时配置的模型单价估算美元费用。任务启动前预留预算；结果不明确的请求保留预留金额。预算是本地保护线，最终账单以服务商的用量页面为准。这里的金额只统计 API 请求，不包含 Codex 账号中无法折算的消耗；切换接入方式也不会把历史 Codex 消耗当成零。
- **本机 Codex 模式：** 记录尝试次数和工具返回的 token。界面明确显示“金额未知”，不会把次数当作美元，也不会把未返回的费用算成零。订阅额度以实际使用账号的规则为准，API 月预算不能约束订阅额度。
- **未接入模型：** 仍可以收集、阅读、筛选和保存个人笔记。

如需暂停分析，在“用量”页面点击“暂停分析”。暂停阻止新的分析任务启动，已经发出的请求可能继续完成。确认账号、网络与用量正常后，再恢复队列。

网页读取与模型分析分别运行。VPS、网络和其他第三方服务的费用，不在模型费用估算中。

## 一轮研究的完成标准

一篇资料进入正式写作前，至少做到：原文可追溯，业务问题和实施方案说得清，阶段没有夸大，效果数字有出处，适用条件已记录，个人判断与原文事实分开。
