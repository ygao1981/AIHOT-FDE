# 模型接入、用量与费用

这份说明针对独立的 `fde-workbench/`。它不使用原项目的 PostgreSQL worker，也不继承旧版多轮评分、语义归组或全文翻译任务。

**个人研究建议先手动选一篇文章分析，再根据结果和账户用量决定是否开启自动分析。** 采集开关、分析开关和自动分析开关相互独立。默认 `FDE_MODEL_PROVIDER=off`，采集和分析也都关闭。打开研究页面、搜索、修改个人笔记、导出 Markdown 不触发模型。

## 两种接入方式

| 事项 | 官方 API：`api` | ChatGPT 登录的官方 Codex CLI：`codex` |
|---|---|---|
| 凭据 | 自己的 `OPENAI_API_KEY` | 用户本人通过官方 CLI 登录；使用独立登录目录 |
| 调用入口 | 固定 `https://api.openai.com/v1/responses` | 配置的官方 `codex` 可执行文件，调用 `codex exec` |
| 文章分析 | 一次 HTTP 请求生成一份研究结果 | 一次 CLI 任务生成一份研究结果 |
| 输出 token 硬上限 | 使用 `max_output_tokens`，包含可见输出和推理 token | 当前未使用未经证实的 token 硬限参数；有字段长度、进程超时和本地输出大小限制 |
| 用量 | 保存 API 返回的输入、缓存输入、输出和推理 token | 保存 CLI `turn.completed` 事件提供的用量；未提供的字段保持未知 |
| 费用 | 按配置单价估算，另有月预算预留 | 金额保持未知，不显示为零元 |
| 失败后 | 不自动重发，不转用 CLI | 工作台不自动重启失败任务，不转用 API；CLI 内部行为另见下文 |

两者必须明确选择，不会自动切换。ChatGPT 登录凭据不能填入 `OPENAI_API_KEY`，工作台不读取、解析或转发 `auth.json` 中的令牌。

API 模式会遵循服务器已有的 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`（也支持其小写名称）。代理只能由运行环境配置，不能由网页请求指定；目标始终是官方 HTTPS 地址，不关闭证书验证。每个请求结束后释放它自己的代理连接资源，不要求额外设置 Node 启动参数。代理是部署方已有的网络信任边界。

官方接入和上限语义参见 [Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)、[Codex 认证](https://developers.openai.com/codex/auth) 和 [非交互运行](https://developers.openai.com/codex/noninteractive)。套餐权限和可用额度以自己的账户当前显示为准，见 [在 ChatGPT 套餐中使用 Codex](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan)。

## 一篇资料会做哪些工作

1. 采集器读取列表和原文，进行 URL 去重。这些是代码任务，不是模型任务。本工作台没有 Jina、付费公众号采集或 X 数据 API 的兜底。
2. 本地规则检查正文长度、AI 相关性和工程实践线索。正文不足 180 字符，以及明显的招聘、直播预告等内容，不进入模型分析。
3. 对候选文章进行一次结构化分析，同时生成中文摘要、业务问题、实施方法、阶段、效果、原文引文、可复用经验、限制和最多三个公众号选题。
4. 本地校验 JSON 字段、文字长度和引文。校验不合格即记录失败，不让模型反复改稿。
5. 保存结果。之后阅读、搜索、标注、选题和导出使用已保存的数据。

单次分数是模型的一次阅读判断。它不是独立交叉验证或原项目的两次评分。公众号选题是编辑建议；不会自动写成公众号长文，也不会自动发布。

## 可控的限制

工作台 `.env.example` 的初始配置为：

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `FDE_DAILY_LIMIT` | 5 | 滚动 24 小时的执行尝试数；不是保证成功的文章数 |
| `FDE_MONTHLY_BUDGET_USD` | 10 | API 模式按 UTC 自然月计算的应用预算，单位美元 |
| `FDE_MAX_INPUT_CHARS` | 16000 | 单篇送入分析的正文字符上限，不是 token 数 |
| `FDE_MAX_OUTPUT_TOKENS` | 2500 | API 请求的输出 token 上限；也进入缓存身份 |
| `FDE_MODEL_TIMEOUT_MS` | 180000 | 单个模型任务的最长等待时间，默认三分钟 |
| `FDE_REASONING` | low | 向支持该参数的模型请求较低的推理强度 |

正文会规范化空白，超出长度时截断。原文可能还有未提供的部分；结果会保留“正文已截断”的说明。输入限制可配置为 2,000–32,000 字符。抓取到的订阅摘要也应标明不完整，不能当作已读完整原文。

默认的五次限制统计已登记的执行尝试。失败、超时和某些本地启动失败也可能占用次数。它不等于五次供应商底层请求，也不等于五篇成功研究笔记。缓存复用不会新增模型请求。停用分析请使用 `FDE_ANALYSIS_ENABLED=false` 或界面的暂停操作，不要把次数上限设为零来代替开关。

正文不足或未通过本地相关性规则的资料，会在登记执行尝试之前停止处理；它们不占日次数、不预留 API 预算，也不会因为这种本地拒绝而触发全局暂停。手动收录仍保留资料，方便阅读、记笔记或补充正文。

## API 费用如何计算

`FDE_API_INPUT_PRICE` 和 `FDE_API_OUTPUT_PRICE` 的单位均为 **美元 / 一百万 token**。启用前核对所选模型的官方价格，变更模型时同步更新单价。代码不查询用户账单，也不自动推断折扣、赠送额度或套餐权益。[官方价格](https://developers.openai.com/api/docs/pricing)

发送前，工作台先做保守预留：

```text
输入预留 token = 完整请求 JSON 的 UTF-8 字节数 + 4096
预留美元 = 输入预留 token × 输入单价 / 1,000,000
         + max_output_tokens × 输出单价 / 1,000,000
```

完整请求包含提示词、文章、结构定义和其他请求字段；额外预留用于消息封装。使用字节数会比常见的“几个字符约等于一个 token”估算法保守很多。预留不假定缓存命中；可用月预算不足时，不发送请求。

成功返回后，记录按实际返回用量计算的保守估算：

```text
估算美元 = input_tokens × 输入单价 / 1,000,000
         + output_tokens × 输出单价 / 1,000,000
```

缓存输入仍按完整输入价计算，因此可能高于实际账单。推理 token 已包含在 `output_tokens` 中，不再次相加。请求固定使用 Standard 对应的 `service_tier=default`，没有另外调用搜索、图片或工具。

这属于工作台的预算控制，不是供应商账户级的绝对消费上限。单价填错、模型别名变化、其他应用使用同一账户等因素不由本地数据库控制。请同时核对官方账户用量。

发生超时或连接中断时，即使本地已终止等待，供应商仍可能完成请求并计费。未知结果保留预留金额，不记为零、不自动重发。有完整 usage 但结果未通过验证时，仍能记录这次已发生的用量。没有 usage 的返回不能据此证明免费。

## Codex CLI 的边界

工作台把文章通过标准输入传入官方 CLI，不把正文写到命令行参数。每次使用独立的临时工作目录，指定只读沙箱；关闭 shell、网页搜索、应用、插件、图片、浏览器、多智能体、记忆等功能。子进程只接收必要的运行环境和独立登录目录，不继承 API 密钥、数据库地址或管理员口令。原始标准输出与错误输出不会直接暴露到应用日志或网页。

CLI 会忽略独立登录目录中的用户配置，保留官方登录能力；`--ignore-user-config` 放在 `exec` 后。不得把其他项目的 Codex 配置、MCP 配置或登录文件拷进这个目录。系统管理策略仍然由 CLI 自己执行，不通过危险权限参数绕过。

本地核对的 CLI 为 `0.172.0-alpha.2`。这说明开发环境中相关命令行参数存在，不代表已经使用你的账户完成真实分析。部署时应核对并固定自己安装的官方版本。`inspectCodex` 和 `npm run doctor` 只执行版本、帮助和登录状态检查，不提交模型任务；通过检查后仍需要一篇真实资料验收。

**一次 CLI 任务可能包含多次内部请求或连接重试。** 工作台只在应用层保证不自动重启失败任务；同时关闭当前 CLI 的无限连接重试功能。当前官方版本禁止覆盖内置 `openai` provider，因此没有伪装成可用的 `model_providers.openai.request_max_retries=0` 配置，也没有为关闭重试而换成自定义 provider。详见 [官方配置参考](https://developers.openai.com/codex/config-reference)。

CLI 的 `maxOutputTokens` 目前不是供应商端硬上限。工作台靠短输出要求、严格字段长度、最大响应大小和超时限制任务，不能据此承诺固定 token 数。多个 `turn.completed` 的 usage 会累加；没有收到用量的失败或中断不能准确反推消耗。

CLI 结果的 `costUsd` 为 null，表示金额未知。套餐额度、已经购买的额外 credits、账户的付费选项及 CLI 自身开销都由官方账户系统决定。不要将“未使用 API key”理解为“保证额外消费为零”。[个人套餐 credits 说明](https://help.openai.com/en/articles/12642688-using-credits-for-flexible-usage-in-chatgpt-personal-plans)

## 缓存与重新分析

缓存键同时包含实际送入的标题、URL、正文、截断标记、提示词与结构版本、接入方式、模型、推理强度、输入和输出限制、超时设置。改变模型或推理强度后不会误复用另一种配置的结果。密钥和单价不进入缓存键，也不会写入模型提示词。

CLI 模型留空时表示使用账户默认模型。默认模型可能随账户设置变化，程序无法离线识别这种变化。需要可重复对照时，请明确填写账户支持的模型名；可用时优先选择固定版本。已有结果不会只因供应商在同一模型别名后切换模型而自动更新。

正常重复排队优先复用同一输入和配置的结果。人工“重新分析”表示明确允许一次新尝试，仍受暂停、次数和 API 预算限制。失败任务不会自行再次消耗额度。恢复暂停与确认重新分析是不同操作。

## 结果能证明什么

`evidence[].quote` 必须可在本次提供的正文中定位。`stageEvidence` 独立保存支持实施阶段的原文；没有阶段证据就降为“原文未披露”。生产阶段还要求明确的已部署表述，并排除明显的未来计划和否定表述。

这些检查能挡住缺失字段、超长输出和凭空捏造的引文，不能完全理解上下文。原文中的自述也不因此变成独立验证。英文或中文之外的阶段表达可能被保守降级；引用真实片段但错误解读含义，也仍需人工核对。写公众号前应检查原文、阶段、效果数字和资料日期。

网页内容始终作为不可信数据传入。测试覆盖了提示注入文本不会变成程序配置或新增工具，但不能证明模型绝不受文章措辞影响。使用严格结构、只读环境和原文引文，是为了缩小错误影响；它们不替代事实核查。

## 本地验证

在 `fde-workbench/` 目录运行：

```bash
node --test tests/analysis.test.mjs
```

测试使用本地 HTTP 假服务、拒绝隧道连接的本地代理和临时假 CLI。覆盖默认关闭、缓存键变化、正文截断、引文与阶段校验、硬输出参数、UTF-8 预留、usage 计费、错误脱敏、超时、重定向不转发凭据、代理兼容、CLI 环境隔离、异常工具中止和非模型诊断命令。它们不会连接真实模型，也不会验证任何 Plus 账户的实际额度。
