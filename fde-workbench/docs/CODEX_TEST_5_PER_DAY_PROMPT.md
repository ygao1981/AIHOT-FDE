## 用户明确授权的额度

- **允许在滚动 24 小时内最多提交 5 次真实 Codex CLI 分析尝试。** 不必每篇再询问我的许可；每次都必须用于明确的验证目的并记录结果。
- 这里的“5”是 5 次**尝试**，不是 5 篇保证成功。失败、超时、`unknown`、手工重试都占用尝试次数；已完成的缓存复用不占新尝试。
- 上次美团文章的 `unexpected_tool` 已产生一条 `unknown` 回执。如果它还在当前滚动 24 小时内，**最多只能再试 4 次**；超过窗口后方可依法按新窗口计数。以研究台 SQLite 的实际开始时间为准，不假设跨午夜就清零。
- 这份授权允许在修复问题、复测安全保护、确认账号正常后，人工**恢复当前暂停**并继续测试其他合格文章。**不授权删除或修改原回执、重置计数、强制改时间、自动重发结果未知请求、提高上限到 5 以上或绕过安全校验。**
- 只用 `codex` provider；不使用 API key，不触发其他付费服务，不自动发布公众号内容。

## 3. 允许真实测试，累计最多 5 次尝试

基线配置为：
```dotenv
FDE_MODEL_PROVIDER=codex
FDE_ANALYSIS_ENABLED=true
FDE_AUTO_ANALYZE=false
FDE_DAILY_LIMIT=5
```

不要覆盖现有 `.env` 的其他配置。修改后按现有部署方式安全重启**唯一**研究台实例。确认原先发出的请求已经停止，且不存在另一个实例，核对备份后可以为本轮已获授权的测试解除 `analysis_pause`；**不要让旧 unknown 自动重试**。

采用逐篇方式测试，先选择至少两篇正文完整、原文可公开阅读的不同来源文章（例如美团技术复盘以外的国内案例和海外 FDE/Agent 工程案例），覆盖：
- 成功返回结构化 JSON；
- 真实原文引文定位；
- 案例的方案、实施阶段、限制和 ROI 不被编造；
- SQLite 分析结果、任务回执和用量统计一致；
- 读页面、搜索、笔记和导出不新增分析；
- 正常重复排队命中缓存，不额外消耗额度。

首次真实请求如果失败，**立即核对安全事件类型与错误原因**。修代码、跑模拟测试后，允许在剩余额度内继续**其他文章**的真实测试。结果未知的旧请求不能自动重发；如果需要手动重试，也必须先确认旧执行已结束，并将它计入最多五次的尝试总数。

如果至少两篇人工分析成功且没有安全异常，可临时设置 `FDE_AUTO_ANALYZE=true`，在剩余尝试数范围内验证：
- 新到的合格来源是否自动入队；
- 无变化或被规则过滤时不启动模型；
- 单并发、上限阻断、失败暂停是否符合预期；
- 笔记与研究库结果仍可查询。

自动分析验证结束后把 `FDE_AUTO_ANALYZE=false`。**若出现任何未查明的工具事件、额度或账本异常，立即关闭自动分析并暂停新任务，先排查，不连续消耗剩余次数。** 不人为制造五次调用来凑数。
